Blistra essential dashboard

Built from one question: what does someone need to know, and do, in the next few seconds of opening the app? Answer: what's urgent, what's next, and what's left today. Everything else is one tap away. Every element maps to a field the dashboard API already returns.

The reading order

  • 1 · Next up — the single most time-critical thing, with its action button. Open → act → close.
  • 2 · Needs attention — only appears when something is overdue or missed. Hidden when empty, so it never becomes noise.
  • 3 · Today's timeline — doses, events and due tasks merged in time order, so there's one list instead of three modules to check.
  • 4 · Habits left — tappable chips, finished ones fade.
  • 5 · Quick log — water, meal, expense, task. Logging is the app's most repeated action, so it's on the home screen.
  • 6 · Today so far / This week / Money — calm summary, below the fold.

Cut from the previous version — and why

  • Life score / streaks — not in the API; invented scores feel arbitrary and can guilt users.
  • Sleep, steps, adherence %, refill stock — no data source yet.
  • Calorie ring / water goal / budget % — the API returns totals, not goals. Showing a ring against a made-up target would mislead. Show totals until goals exist.
  • Habit times — habits have no time-of-day field, so they stay a checklist, not timeline entries.
  • AI insight card, 8-week heatmap, vitals grid — nice, but not decision-critical on the home screen. Vitals live in Health.

Data mapping (DashboardResponse)

  • Next up / timeline — medicines.dosesToday (scheduledAt, status), planner.todayEvents, planner.todayTasks, health.upcomingAppointments
  • Needs attention — planner.overdueTasks; doses with a past scheduledAt and no takenAt
  • Habits — habits.todayHabits, completedToday / expectedToday
  • Today so far — diet.waterTotalMilliliters, diet.nutrition.caloriesKcal, finance.today (per currency)
  • This week — week.completedTasks, habitCompletions, activeDays
  • Money — finance.owedToYou / youOwe (shown only when non-zero)
  • Resilience — each section can be unavailable; render that card as "Couldn't load · Retry" and keep the rest.
